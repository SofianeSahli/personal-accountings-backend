# 002 — Accounts: Design

> Status: Approved (2026-11-14)
> Requirements: [requirements.md](./requirements.md) · Contract: [contract.md](./contract.md)

## Overview

Port Shop Keeper's `app/Modules/Identity` into `app/Modules/Identity`, file by file, keeping its actions, rules and constants. Every change from Shop Keeper is listed in **Adaptations** below; anything not listed behaves as in Shop Keeper. Shop Keeper's tests are ported with it and renamed with `REQ` ids, and cookie-mode tests are added.

## Adaptations from Shop Keeper

| # | Shop Keeper | Here | Why |
|---|---|---|---|
| A1 | `bigint` ids | Ordered UUIDs (`HasUuids`, `CHAR(36)` ascii) on `users`, `email_codes`, `pending_sign_ins`, `personal_access_tokens`; ascii `uuid` FKs | CLAUDE.md "Keys" |
| A2 | `users`/PAT migrations in the app, Identity adds columns | Identity owns and creates all its tables, one migration each, fresh | No data to keep; module owns its tables |
| A3 | Field codes mapped by hand (`password.min` → `password.too_short`) | Codes generated by `ValidationCodes` as `<field>.<rule>` | Spec 001, REQ-6.3 |

| A6 | `abstract IdentityRequest` base | Each request is `final` and builds its rules from a `final` `IdentityRules` class (static methods) and an `IdentityRules::prepareEmail()` call in `prepareForValidation` | Arch test REQ-5.9 (every class final), no `Base*` |
| A7 | `SignInResult` in `Actions/` | `Support/SignInResult` | Actions expose only `handle` |
| A8 | Token mode only | Cookie mode added (see **Modes**) | REQ-6.1 |
| A9 | Tokens never expire | 90 days (`sanctum.expiration`) | REQ-6.4 |
| A10 | `/me` embeds `shop` | No shop/household; `locale` added | Identity depends on nothing |

## Data

All UUID columns: `uuid(...)->charset('ascii')->collation('ascii_bin')`.

| Table | Columns | Indexes / FKs |
|---|---|---|
| `users` | `id` uuid PK; `name` varchar(120); `email` varchar(255); `email_verified_at` ts null; `password` varchar null; `google_id` varchar null; `phone` varchar(16) null; `locale` varchar(8) default `fr`; `terms_version` varchar(20); `terms_accepted_at` ts; `two_factor_enabled_at` ts null; `password_failed_attempts` tinyint unsigned default 0; `password_locked_until` ts null; `remember_token`; timestamps | unique `email`, unique `google_id` |
| `sessions` | Laravel's: `id` varchar PK (session id, not a record key); `user_id` uuid null; `ip_address`; `user_agent`; `payload`; `last_activity` | index `user_id`, `last_activity`; no FK (Laravel's default) |
| `personal_access_tokens` | Sanctum's, with `id` uuid PK, `tokenable_type` + `tokenable_id` uuid; `name`; `token` char(64); `abilities`; `last_used_at`; `expires_at`; timestamps | unique `token`; index (`tokenable_type`, `tokenable_id`); index `expires_at` |
| `email_codes` | `id` uuid PK; `user_id` uuid FK; `purpose` varchar(20); `code_hash`; `failed_attempts` tinyint; `expires_at`; timestamps | unique (`user_id`, `purpose`); FK `users` cascade on delete |
| `pending_sign_ins` | `id` uuid PK; `user_id` uuid FK; `device_id` uuid **null** (null = web mode); `token_hash` char(64); `code_hash`; `failed_attempts`; `expires_at`; timestamps | unique `token_hash`; FK `users` cascade on delete |

Cascades go from `users` to its own auth records only, never to money records (CLAUDE.md "Deleting").

Migrations (`2026_11_14_00000{1..5}_create_<table>_table.php`), one table each. Sanctum's own migration is not published; `PersonalAccessToken extends Laravel\Sanctum\PersonalAccessToken` adds `HasUuids` and is registered with `Sanctum::usePersonalAccessTokenModel()`. Sanctum's `{id}|{secret}` token format works with a UUID id.

## Modes (REQ-6.x)

- `bootstrap/app.php` calls `$middleware->statefulApi()`. Sanctum then starts the session, encrypts cookies and checks CSRF **only** for requests from `SANCTUM_STATEFUL_DOMAINS`.
- `Support/SignInMode::of(Request)` returns `Web` when `EnsureFrontendRequestsAreStateful::fromFrontend($request)` and the request has a session, else `Device`.
- Requests that finish a sign-in (`ConfirmEmailRequest`, `PasswordSignInRequest`, `GoogleSignInRequest`) require `device_id` only in `Device` mode (`Rule::requiredIf`). The controller passes `SignInMode` and the device id (or null) to the action as a `Support/SignInTarget` DTO.
- `FinishSignIn` (two-step check) then calls either `IssueDeviceSession` (token, as Shop Keeper) or `StartWebSession` (`Auth::guard('web')->login($user)` + `session()->regenerate()`). `PendingSignIn.device_id = null` records web mode; `ConfirmSignInCode` refuses with `auth.pending_invalid` when the confirming request's mode differs.
- `LogoutController`: `Device` → delete current token; `Web` → `Auth::guard('web')->logout()`, invalidate session, regenerate CSRF token.
- `auth:sanctum` (Sanctum guard `['web']`) already accepts either a session or a bearer token.
- Sanctum's `AuthenticateSession` middleware is enabled so a session ends when the password hash changes; `ResetPassword` also deletes the account's `sessions` rows (A13).
- `SessionResource` omits `token` in web mode.

## Authorization

No household data, so no policy. Authenticated routes act only on `$request->user()`.

## Error codes

New in this spec: `email.taken` 409, `code.invalid` 422, `auth.invalid_credentials` 401, `auth.email_unconfirmed` 403, `auth.password_locked` 429, `auth.pending_invalid` 401, `auth.google_invalid` 401, `auth.google_unavailable` 503, `auth.google_email_conflict` 409, `auth.terms_required` 422, `two_factor.already_enabled` 409, `two_factor.not_enabled` 409, `auth.csrf_mismatch` 419.

`auth.csrf_mismatch`: Laravel turns `TokenMismatchException` into an `HttpException` 419, which the renderer currently maps to `500 server.error`. `ApiErrorRenderer` gets one more `match` arm. This adds a code to spec 001's contract; its `contract.md` is updated in the same change.

## Risks / alternatives considered

- **Mode detection by origin.** A Capacitor app sends an `Origin` too (`https://localhost` on Android, `capacitor://localhost` on iOS). If those origins were listed in `SANCTUM_STATEFUL_DOMAINS`, mobile requests would be treated as web. The stateful list must hold only the web app's domains; this goes into the README and `.env.example`. Separate paths per mode were rejected by the owner.
- **Session id is not a UUID.** `sessions.id` is Laravel's random session id; CLAUDE.md's UUID rule covers record keys, and changing it would mean replacing Laravel's session handler.
- **Expired rows are not pruned** (non-goal). They are refused at use and replaced on the next send.
